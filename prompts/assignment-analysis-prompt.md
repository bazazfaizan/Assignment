I am completing an SDET practical assignment. Use the attached assignment as the source of truth.

Help me produce a professional, maintainable submission that demonstrates strong SDET thinking. I want:
1. Risk-based top 10 test scenarios ranked by business/technical risk.
2. A precise discrepancy analysis of the supplied FR-05 API response, without inventing requirements.
3. At least 8 detailed UI/API test cases.
4. Executable Playwright TypeScript tests using Page Object Model covering keyboard navigation, Enter/Escape, filtering, selection, submission, and success/error states.
5. API automation validating the FR-05 contract, data types, timestamps, BCP 47 locale, matching suggestion_list, and at least two negative cases.
6. A transparent AI reflection describing AI usage, concrete human modifications, and AI limitations.
7. A clean Git repository structure and README.

Important constraints:
- Do not invent an API endpoint or authentication mechanism that the assignment does not specify.
- Explicitly identify assumptions.
- Treat the assignment text as the source of truth.
- Distinguish standards validity from business-rule expectations.
- Prefer maintainable automation design and clear failure diagnostics.
- The final submission should demonstrate independent QA judgment, not blind AI-generated content.
